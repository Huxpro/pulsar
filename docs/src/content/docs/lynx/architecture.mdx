The path a tap takes from your Lynx code to a vibration on the device:

```text
┌─────────────────────────────────────────────────────────┐
│  Your Lynx app                                          │
│  ┌──────────────────────────────────────────────────┐   │
│  │ Event handler (background thread)                │   │
│  │   bindtap={() => Presets.dogBark()}              │   │
│  └────────────┬─────────────────────────────────────┘   │
│               │ NativeModules.PulsarModule              │
│               ▼                                          │
│  ┌──────────────────────────────────────────────────┐   │
│  │ PulsarLynxModule (Obj-C, <LynxModule>)           │   │
│  │   play(name)                                     │   │
│  │   parsePattern(...) / patternPlay(id)            │   │
│  │   realtimeSet(amp, freq) / realtimeStop()        │   │
│  └────────────┬─────────────────────────────────────┘   │
│               │                                          │
│               ▼                                          │
│  ┌──────────────────────────────────────────────────┐   │
│  │ Pulsar Swift SDK                                 │   │
│  │   CHHapticEngine (Core Haptics)                  │   │
│  └──────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

## The JS surface

`lynx-pulsar` exports three things:

- **`Presets`** — 151 preset functions plus `Presets.System.*` (system feedback styles). Each is a synchronous `void` call that posts a play command to the native module.
- **`usePatternComposer(pattern?)`** — pattern composer hook. Supply a `Pattern` (`discretePattern` + `continuousPattern` envelopes); the hook parses it on mount and exposes `{ play, stop, parse, isParsed }`. Native resources release on unmount.
- **`useRealtimeComposer()`** — realtime composer hook. Returns `{ set(amplitude, frequency), playDiscrete(amplitude, frequency), stop, isActive }`. Call `set` at touch-event rate to drive continuous haptics; the bridge debounces if backed up.

The hooks are plain `useRef`-backed — Lynx uses a different threading model than React Native Reanimated, so the upstream `'worklet'` directives are not used here. The full API surface is on the [SDK reference](/pulsar/sdk/lynx/) page.

## A note on threading

ReactLynx runs your JSX on two threads: a **main thread** for synchronous snapshot evaluation, and a **background thread** for event handlers, effects, and most hooks. `NativeModules.PulsarModule` is only available on the background thread — calling a Pulsar API from main-thread evaluation will hit an undefined module and silently no-op.

In practice this means:

- ✅ **Safe** — call from `bindtap` / `bindtouch*` handlers, `useEffect`, async callbacks
- ❌ **Unsafe** — call from a render expression top-level, a `static` initializer that runs at snapshot eval time

The adapter guards `NativeModules` with a `typeof` check so main-thread evaluation doesn't throw; if your haptics simply don't fire, the call site likely ran on the wrong thread.

## The host

Your Lynx app needs a host that registers `PulsarLynxModule` so JS can reach it. The Lynx Pulsar fork ships such a host, built on top of `LynxExplorer`:

- The Pulsar Swift SDK is linked into the app.
- `PulsarLynxModule.{h,m}` is registered via `[globalConfig registerModule:PulsarLynxModule.class]`.
- `Info.plist` carries the Lynx Pulsar bundle ID and display name; AppIcons are derived from upstream PulsarApp's 1024×1024 PNG.

If you are integrating into an existing iOS host, the integration is the same as any Lynx native module — copy the `LynxExplorer/modules/Pulsar/` Swift sources and the `PulsarLynxModule` Obj-C files, register the module in your `LynxInitProcessor`, and pin `IPHONEOS_DEPLOYMENT_TARGET ≥ 15.0`. The [adapter source](https://github.com/Huxpro/pulsar/tree/lynx-port/lynx/lynx-pulsar) is small enough to copy in.

## The bundle pipeline

`xcodebuild -configuration Release` runs an Xcode Run Script Build Phase ("Bundle Pulsar Lynx code") after compile:

```sh
LYNX_APP_DIR="${LYNX_PULSAR_APP_DIR:-$HOME/github/pulsar/lynx/lynx-pulsar-app}"
cd "$LYNX_APP_DIR" && npm run build  # rspeedy build

RES_DEST="$BUILT_PRODUCTS_DIR/$UNLOCALIZED_RESOURCES_FOLDER_PATH/Resource"
mkdir -p "$RES_DEST"
cp "$LYNX_APP_DIR/dist/main.lynx.bundle" "$RES_DEST/homepage.lynx.bundle"
```

The phase declares `outputPaths`, so Xcode's implicit CodeSign that follows correctly hashes the new file. Debug builds skip this phase — the host's original "Bundle URL" home card stays usable for `rspeedy dev` iteration.

The host loads `file://lynx?local://homepage.lynx.bundle?fullscreen=true` on launch and resolves it to `<app>/Resource/homepage.lynx.bundle` — i.e. the file the build phase just wrote.

## Self-contained assets

`lynx.config.ts` sets:

```ts
output: {
  dataUriLimit: { image: Number.MAX_SAFE_INTEGER },
},
```

This inlines all 151 preset PNGs and the tab-bar icons as base64 dataURIs. The bundle is ~6.7 MB but has zero runtime HTTP dependencies — required because `local://` loading has no host to resolve image URLs against.

## Why no Home tab in the demo

The upstream Pulsar app's Home tab pairs a phone with the browser-based playground over WebSocket. Lynx does not expose WebSocket today, so the Home tab is hidden in the demo (commented JSX, restorable by uncommenting + flipping the default `activeTab`). Presets / Playground / Demos all work as expected.
