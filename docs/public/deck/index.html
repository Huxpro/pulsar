Context

What is Pulsar?

A cross-platform, designer-grade haptics SDK by Software Mansion — native Swift on iOS, native Kotlin on Android, with a polished React Native adapter shipping in production.

It includes 151 hand-crafted haptic presets (Anvil, Heartbeat, BalloonPop…), a PatternComposer for arbitrary discrete + continuous patterns, and a RealtimeComposer that streams amplitude/frequency in real-time.

The official PulsarApp demo (Expo Router, ~5,000 LOC of UI) is the polished showcase — 4 tabs, 7 demo screens, full design system. It's the artifact we're porting.

iOS Swift SDK Android Kotlin SDK React Native (TurboModule) 151 haptic presets Apache 2.0

What you feel

Tap BreakingWave on iPhone Pro — three measured taps, then a stronger landing. Not a buzz. Not a click. A texture.

Why port it

Pulsar is a perfect test case for Lynx Native Modules — non-trivial sync return values, real-time streaming, hooks across the dual-thread boundary, and 1,300+ lines of mostly-mechanical TS to translate.

It also looks good. Hackathons reward visible craft.

The Move

A slopfork.

A slopfork is the agent-era version of a port: we don't rewrite from scratch and we don't translate one-to-one — we let the model re-derive each layer from a reference, holding shape constant where it can and admitting platform reality where it can't.

For Pulsar that means three layered repros:

  • lynx-pulsar — the Native Module library (Swift/Kotlin bridges + TS surface)
  • lynx-pulsar-demo — the minimal SDK test harness (ports react-native/PulsarApp/)
  • lynx-pulsar-app — the polished port of the official PulsarApp/

Each one is a known-good twin the next layer can fall back to when ReactLynx breaks in surprising ways.

The shape of the edit

Same hook. Two worlds.

usePatternComposer — the hook a Pulsar app uses to parse and play a pattern — written once for React Native, once for Lynx. The structure is identical. The differences are mechanical.

React Native react-native-pulsar/src/usePatternComposer.ts

import { useCallback, useEffect } from 'react';
import Pulsar from './NativeRNPulsar';
import type { Pattern, PatternComposer } from './types';
import { useSharableState } from './useSharableState';

// workaround for RN prototype caching issue
Pulsar.PatternComposer_play;

export default function usePatternComposer(pattern?: Pattern): PatternComposer {
  const patternId = useSharableState(-1);

  const play = useCallback(() => {
    'worklet';
    const id = patternId.get();
    if (id !== -1) {
      Pulsar.PatternComposer_play(id);
    }
  }, []);
  // ... stop, parse, isParsed — same shape
}

Lynx lynx-pulsar/src/usePatternComposer.ts

import { useCallback, useEffect, useRef } from '@lynx-js/react';
import Pulsar from './NativePulsar';
import type { Pattern, PatternComposer } from './types';



// no prototype workaround needed


export default function usePatternComposer(pattern?: Pattern): PatternComposer {
  const patternIdRef = useRef<number>(-1);

  const play = useCallback(() => {


    const id = patternIdRef.current;
    if (id !== -1) {
      Pulsar.patternPlay(id);
    }
  }, []);
  // ... stop, parse, isParsed — same shape
}

Net result: import path, the worklet directive, and the method-name prefix are gone. The shared-mutable-state primitive becomes a plain useRef — Lynx's dual-thread model already runs hooks on the background thread, so there's no shared-memory hop to bridge.

Layer ③ · ReactLynx App · the not-so-mechanical parts

Where Lynx actually differs.

The adapter port is mechanical. The UI port is not. ReactLynx looks like React but enforces a different runtime contract — and the things that break first are the things React idioms make you reach for first.

No conditional JSX
{cond && <X/>} and ternaries crash the dual-thread snapshot system. Render both branches, toggle style={{ display: ... }}. Every tab panel and every demo sub-view in this app exists in the tree at all times.
display: none isn't enough
In a flex container, display: none doesn't reliably hide a child. The working pattern is position: absolute + width/height: 100% + zIndex, with overflow: hidden on the parent.
No .map() with dynamic keys
Using key to force remount, or toggling display:none inside .map(), both trigger snapshotPatchApply / insertBefore crashes. Use opacity + absolute positioning inside lists.
Elements + events
<View> → <view>, <Text> → <text>, onPress → bindtap, onTouchStart → bindtouchstart. Text MUST be inside a <text>; bare strings in views are a build error.
CSS reality check
text-transform isn't supported. All lengths need units ("24px", not 24). display: flex defaults to row. overflow: scroll is unsupported — use <scroll-view scroll-y>. <image> needs explicit pixel dimensions.
No gesture-handler
The Playground's swipe-to-draw and the Slider demo were rebuilt on raw bindtouchstart/move/end. The Sensor Haptics demo's accelerometer-driven dot lost its accelerometer entirely (no API yet) — fell back to touch drag with the original physics intact.
Dual-thread guard for NativeModules
NativeModules only exists on the background thread. The main thread evaluates JSX snapshots. The adapter wraps with typeof NativeModules !== 'undefined' so the module file is safe to import on both threads.

Layer ③ · the slopfork

What carried across.

Component code didn't survive — the JSX, the CSS, and the event model are too different to copy. But the shape of the app did: layout, design tokens, copy, animation timings, preset metadata.

100% Design tokens carried over Navy #001A72, sky #e1f3fa, border #38ACDD, offset shadow — pixel-identical to the original.
100% Preset metadata reused All 151 names, descriptions, tags, and durations come from the source app. The preset images are the original PNGs.
0% JSX components reused Every component is rewritten. But there's only one file (App.tsx, 1,349 LOC) because multi-file imports trigger snapshot errors.

Things the slopfork lost

  • React Navigation → re-implemented as 4 always-mounted <view> panels with show/hide
  • Expo Router file-based routing → a single state variable activeTab
  • react-native-gesture-handler → raw touch events
  • SVG icons → exported PNG sprites (8 of them, in two states each)
  • Accelerometer → touch-drag fallback (graceful degrade, with a label saying so)

Things the slopfork gained

  • A single bundle that boots into LynxExplorer with the dev server's QR code
  • 3D press effect on every button (CSS transforms — no Reanimated needed)
  • A preset playback progress ring driven by a setInterval on the background thread (no worklet boundary to cross)
  • A dual-thread story that's easier to explain than RN's: "snapshot on main, everything else on background"

The Meta

Harness Engineering, applied.

The interesting deliverable isn't the app. It's the recipe for getting an agent to do this kind of port reliably. Eight things we deliberately built into the loop:

01

Layered AGENTS.md memory

Two files: lynx/AGENTS.md (adapter + Explorer) and lynx/lynx-pulsar-app/AGENTS.md (app port + Lynx CSS rules). Routed from CLAUDE.md with "read this first" headers.

02

PRD-driven execution

Five PRDs (prd-lynx-adapter, android-support, app-port, bugfix-layout, demos-hifi) each carrying a Verification Protocol: lynx-docs check → build → DevTool screenshot → console-error check per story.

03

Known-good twin as oracle

The minimal lynx-pulsar-demo stays canonical for "what definitely works in ReactLynx." When the polished app breaks, the bugfix PRD's answer is "copy the demo's CSS."

04

Closed-loop visual verification

The lynx-devtool skill takes a screenshot after every build. Errors come from get-console. Headless Chrome captures the web preview for the deck. No human-in-the-loop screenshot review needed.

05

/goal Stop hook

Binds the agent to a long-running deliverable (this deck, that PRD) until the condition holds. Stops are blocked until the work is done — no premature "should I continue?"

06

Parallel subagents

Explore for read-only lookups; general-purpose for full multi-step subtasks (mining session JSONLs while the main agent runs the dev server and captures screenshots). Independent work runs concurrently.

07

Platform constraints become harness rules

"Keep everything in one App.tsx" isn't a style preference — it's a hard rule because multi-file imports trip ReactLynx's snapshot system. Codified in AGENTS.md, not in reviewer's head.

08

Personal mistake log

The user's global CLAUDE.md carries five engineering principles ("说不清解决什么问题的改动，就不该做" · "编译通过 ≠ 能用") harvested from prior pushbacks. Lessons travel across projects.

Repeatable

The slopfork recipe.

If you want to do this for another React Native package — Reanimated, Skia, Gesture Handler, anything with a Native Module shape — here's the order that worked:

① Port the adapter first
It's mostly mechanical. Lock down the API surface, write a sync-return test harness (test-sync-returns/), then touch any UI.
② Build a minimal demo before the polished one
A 5-screen test harness that exercises every API call. When the polished port breaks, you have a known-good reference and a place to bisect.
③ Codify platform constraints in AGENTS.md
Don't trust the agent to re-derive "ReactLynx hates conditional JSX" every session. Write it down, route it from CLAUDE.md, link from PRDs.
④ One PRD per coherent unit of work, with a Verification Protocol
Lynx-docs lookup → build passes → DevTool screenshot → console-error check. Every story. No skipping the visual verification step.
⑤ Don't refactor without a concrete bug to point at
"说不清解决什么问题的改动，就不该做." Compile-passing is not the same as working. End-to-end verify on device before declaring done.
⑥ Treat the agent as a colleague, not a worker
Goal hooks, durable memory, layered repros, parallel subagents. You're not asking it to write code — you're shipping a project together.
